# Client probe (ClientProbe + LuaProbe) — what the client does with server responses

Companion to the server dump (`RPC_DUMP=1`): the server writes what it sent, the probe writes how the client took it.
Two layers, one line format: `<epoch_ms>\t<seq>\t<ue4ss|lua>\t<type>\t<text>`.

| Layer | Where | What it writes |
|---|---|---|
| UE4SS mod `ClientProbe` | `game/ue4ss/Mods/ClientProbe` (both installs) | `EVT` client events (210 classes of `UTGFEventArgs`: `ErrorCode`, `TGFRsp` — the server response as an object), `WIN` opened windows (alert/toast texts), `CALL`/`ERR` service function calls (**disabled**: crashes the game, see below), `SNAP` (F10) snapshot of all service fields, `MARK` (F11) marker |
| Lua probe `LuaProbe` | since 04.11 — debug pak `zzzzzzzz_LuaProbe_P` (`debug\luaprobe`, installed/removed by `install_luaprobe.ps1`; not shipped to the launcher or Robot), `Game/System/Match/LuaProbe.lua`, starts in the lobby from its own wrapper of the original match button | `LCALL`/`LRET` calls of UI and service Lua module functions (Mail, Chat, Social, Team, PVP, Game.Service…), `FIELD` first read of a field on a proto object `UTGFProtoTgf*` or an `FTGF*` struct — which response fields the client actually reads, `TRACE` (behind a flag) all Lua calls from selected files |

Logs: `probe/logs/<client>_<date-time>_ue4ss.log` and `…_lua.log`. The client is `steam` (main install) or
`alt` (`C:\Games\Dungeonborne`, which has `local_save.txt`); each has its own file, writing in parallel is fine. The first
`HDR` line holds `steam_id` — that is the session's `open_id` on the server.

## How to capture
1. Backend with the dump: `RPC_DUMP=1 cargo run` (the server also writes `rpc_dump/OUR.jsonl` — time, `who` = open_id, body
   as JSON; pushes from other players via the hub land there too).
2. Start one or both clients, do the action. Before the action you can press **F11** (a marker in the log),
   after it **F10** (a snapshot of what the client stored in its services).
3. Merge:
   ```
   python -I tools/probe_timeline.py --grep mail          session timeline, only lines about mail
   python -I tools/probe_timeline.py --kinds ERR,WIN,S2C   errors, windows and server responses
   python -I tools/probe_timeline.py --fields             which fields the client reads and which the server did not send (✗)
   python -I tools/probe_timeline.py --summary            counters per RPC, event, call
   ```
   By default the last session is taken (logs within 30 min of the newest one), `--all` — everything, `--out file`.

## Settings
- `game/ue4ss/Mods/ClientProbe/config.txt` — layer switches, limits (`call_limit` — how many calls of one function
  to write in full, after that every 500th), dump depth, exclusions by function name. `enabled = 0` — turn off.
- `game/ue4ss/Mods/ClientProbe/lua_config.txt` — Lua probe: modules, `fields`, `trace`/`trace_filter`, `wrap_loaded`.
- Config edits go to `backups/ue4ss/Mods/ClientProbe`, then copy to both installs; they are read at game start
  (the Lua probe — on entering the lobby).
- Target lists are generated by `python -I tools/gen_probe_targets.py` from `ue4ss/CXXHeaderDump`
  (→ the mod's `targets.lua` and `LuaProbeTargets.lua` in the pak). Pak: `debug\luaprobe\install_luaprobe.ps1`
  (builds `zzzzzzzz_LuaProbe_P.pak` and installs it into the F:/E: installs, game closed; `-Remove` — uninstall).

## Crash on 31.10 and what changed
The first version crashed the game on login ("FMallocBinned2 Attempt to realloc an unrecognized block", stack through
UE4SS.dll, right after SyncPlayerInfo; 3 of 3 automated runs). The log broke off while dumping events with string fields
(`UserNickName` in `TGFUpdateUserInfoEvent`). Likely cause — reading `FString`/`FText` of live objects through UE4SS
(the game's string buffer is freed from the Lua side), plus the dump went deep into foreign objects (login window widgets).
Fixed:
- strings (`StrProperty`/`TextProperty`) are not read anywhere — neither fields, nor array elements, nor hook parameters
  (the parameter is not even `get()`-ed); the log shows `<str>` / `<text>`. Numbers, bools, FNames, class names are read;
- recursion goes only into the root object (event, window arguments, service in a snapshot) and protocol data `TGFProto*`;
- the probe leaves auto instances (`-dbserver` / `-dbclient`, `skip_cmdline`) alone: no log, no subscriptions, no hooks;
  it starts from the game thread after the command line is read (as in DungeonborneRuServer);
- toast/alert/error texts are now written by the Lua probe (`LERR`/`LERRRET`: wrappers of `UE.UToastWindow.ShowToast*`,
  `ShowAlert`, `PromptProtocolError`, `GetProtocolErrorText`) — UnLua copies strings into Lua by itself.
The **`-dbprobe`** command-line flag turns the probe on (both layers) bypassing `enabled = 0` and `skip_cmdline` — for
automated checks in dbtest runs without enabling it for the user; the log is then `<client>-srv_…` / `<client>-cli_…`.
Tested on UE4SS API stubs (plain Lua 5.4), not in game. In the installs the probe is off (`enabled = 0`) until
checked: enable one layer at a time, first `config.txt` (UE4SS), account login and lobby, then `lua_config.txt`.

**Bisection on 31.10** (automated dbtest runs with `-dbprobe`, client C:\Games\Dungeonborne): `events=1 windows=0 services=0` — passed
(login → lobby → match → connected, the Lua probe too: LCALL/LRET and FIELD are written); `events=0 services=1` — the same crash
even with `hook_params = simple` (541 hooks). Conclusion: the heap is corrupted by **UE4SS hooks on service functions** (probably a conflict with
UnLua, which replaces functions called from Lua). `services = 0` by default — do not enable; Lua service calls
are written by the Lua probe. Windows (`windows=1`) were not checked in the bisection — one events+windows run is needed.

## Limits and risks
- Hooks catch functions called through UE reflection (from BP and Lua); internal C++ without a UFunction is not visible.
- `FIELD` works if UnLua lets you replace `__index` of a class/struct metatable — the first in-game check:
  `_lua.log` must have the line `HDR поля: обёрнуто N …` (the probe's literal log text) with N > 0 and `FIELD` lines after a window opens.
- Wrapping already loaded Lua modules: a handler subscribed before the wrap will not be unsubscribed via the wrapper (functions are compared
  by reference). If the UI starts acting strangely — `wrap_loaded = 0` (or `enabled = 0`).
- `TRACE` is heavy — enable it for the duration of one action.
- A headless server (`-dbserver`) from the same install also writes a ClientProbe log (same client name).
- The probe does not touch the anticheat: only game functions and objects, as in the other mods.
